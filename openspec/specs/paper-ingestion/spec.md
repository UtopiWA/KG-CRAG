# Paper Ingestion Specification

## Purpose

为受控科研论文语料建立确定性、可追溯且可安全重跑的摄取能力，把校验后的原始 PDF 与元数据转换为结构化文档和章节感知 Chunk，同时保留解析质量、版本和失败诊断信息。

## Requirements

### Requirement: 可审计的 pilot 语料清单

系统 MUST 从已通过 PDF 签名、文件大小和 SHA-256 校验的原始语料中维护一个包含 10–20 篇论文的版本化 pilot 清单。每条记录 MUST 使用稳定论文标识引用原始 PDF/元数据，并 MUST 记录选择理由和至少一个版面标签；整个清单 MUST 覆盖普通文本、双栏、表格、公式和异常版面。

#### Scenario: 加载有效 pilot 清单

- **WHEN** pilot 清单包含 10–20 个唯一标识，且每个标识都能解析到哈希有效的 PDF/元数据对
- **THEN** 系统 MUST 按清单顺序返回相同论文集合及其版面标签，并记录清单内容哈希

#### Scenario: pilot 记录缺失或校验失败

- **WHEN** pilot 清单包含重复标识、未知论文、缺失版面标签或哈希不一致的原始文件
- **THEN** 系统 MUST 在开始解析前以不可重试输入错误拒绝该清单，且 MUST 不创建部分 pilot 产物

### Requirement: 原始输入校验、不可变性与元数据规范化

系统 MUST 在解析前校验 PDF/元数据配对、可信工作区内路径、PDF 签名、文件大小和 SHA-256，并 MUST 将标题、作者、年份、DOI、arXiv ID、其他外部 ID、来源地址和获取信息规范化为严格数据契约。Paper ID MUST 按 DOI、无版本 arXiv ID、其他受支持外部 ID、规范化标题哈希的固定优先级生成；摄取过程 MUST 只读 `data/raw`。

#### Scenario: 同一来源生成稳定论文记录

- **WHEN** 同一 PDF 与语义等价的元数据在相同规范化规则版本下重复摄取
- **THEN** 系统 MUST 生成相同 Paper ID、规范字段和输入 SHA-256，并保留原始外部标识与获取来源

#### Scenario: 冲突元数据被显式报告

- **WHEN** PDF 文件名、元数据中的论文标识或已记录 SHA-256 相互冲突
- **THEN** 系统 MUST 将该论文标记为失败并给出有限的结构化诊断，MUST NOT 猜测标识或修改原始文件

#### Scenario: 工作区外路径被拒绝

- **WHEN** 输入元数据把 PDF 指向配置的原始语料目录之外或指向非普通文件
- **THEN** 系统 MUST 在打开该目标前拒绝输入，且错误信息 MUST NOT 暴露无关的本机路径或凭据

### Requirement: 带位置与警告的结构化 PDF 解析

系统 MUST 通过可替换的 Parser 契约把 PDF 转换为严格校验的结构化文档。解析结果 MUST 保存论文标识、输入哈希、解析器名称与版本、页数，以及按页组织的 Section/Block；每个文本 Block MUST 至少包含一基页码、稳定顺序、文本和页面坐标。无法可靠恢复的双栏顺序、表格、公式、图片或异常字符 MUST 通过带页码和严重级别的 ParseWarning 显式记录。

#### Scenario: 文本 PDF 保留页级定位

- **WHEN** 解析器收到未加密且包含可提取文本的有效 PDF
- **THEN** 系统 MUST 生成顺序确定的页面与 Block，并使每个非空 Block 能回溯到原 PDF 页码和坐标

#### Scenario: 复杂版面采用受控降级

- **WHEN** 页面包含疑似多栏、跨栏标题、表格、公式或无法分类的内容块
- **THEN** 系统 MUST 保留可提取文本和原始位置，按确定性规则排序，并 MUST 为不确定结构写入警告而不是静默声称完整恢复

#### Scenario: 加密、损坏或无文本 PDF

- **WHEN** PDF 无法打开、需要密码、超过配置页数/大小上限，或全部页面都没有达到最低文本阈值
- **THEN** 系统 MUST 以可诊断状态终止该论文的解析，不生成成功的结构化文档，并允许批次继续处理其他论文

### Requirement: 确定性清洗且保留溯源

系统 MUST 以版本化配置执行确定性正文清洗，包括重复页眉页脚识别、软连字符处理、受控换行连字符修复、非法控制字符处理和相邻重复块清理。清洗 MUST 保留从输出文本到原始页码及 Block 的映射；任何可能造成内容损失的规则 MUST 受阈值约束并产生统计或警告。

#### Scenario: 重复噪声与断词被稳定清理

- **WHEN** 多页文档在配置的页边区域重复出现同一页眉页脚，且正文包含可判定的软连字符或跨行断词
- **THEN** 系统 MUST 在相同配置下生成字节一致的清洗文本，移除符合阈值的重复噪声并保留受影响页码统计

#### Scenario: 低置信度清洗不静默删除

- **WHEN** 重复内容未达到配置页数比例、连字符边界含公式/代码，或字符替换无法安全判定
- **THEN** 系统 MUST 保留原内容或采用无损替代，并 MUST 记录对应警告或计数，而不是执行不可审计的删除

### Requirement: 章节感知且稳定的 Chunk

系统 MUST 按识别出的章节边界和版本化切分配置生成 Chunk，配置 MUST 包含目标、最小、最大和重叠 Token 数及 Token 计数器标识。每个 Chunk MUST 包含稳定 Chunk ID、Paper ID、章节、起止页码、顺序、文本、Token 数、内容 SHA-256 和处理版本；普通 Chunk MUST NOT 跨越章节边界，且不得生成空文本或反向页码范围。

#### Scenario: 相同输入产生相同 Chunk

- **WHEN** 对相同规范论文、结构化文档、解析器版本、清洗规则和切分配置重复运行
- **THEN** 系统 MUST 生成数量、顺序、Chunk ID、内容哈希、页码范围和文本均相同的 Chunk 序列

#### Scenario: 长章节按上限与重叠切分

- **WHEN** 单个章节超过最大 Token 数且存在合法切分边界
- **THEN** 系统 MUST 优先在段落或句子边界切分、维持配置的受限重叠，并确保除不可分割单元外的 Chunk 不超过最大 Token 数

#### Scenario: 配置或内容变化形成新处理版本

- **WHEN** 输入哈希、解析器版本、清洗规则、Token 计数器或切分配置发生变化
- **THEN** 系统 MUST 计算新的处理版本与相应 Chunk ID，且 MUST NOT 用新产物静默覆盖旧版本

### Requirement: 版本化产物与原子运行清单

系统 MUST 把结构化文档写入 `data/interim`，把规范 Paper、Chunk 和运行结果写入 `data/processed`，并使用由输入 SHA-256、解析器版本和规范化配置哈希共同确定的处理版本隔离产物。每次运行 MUST 生成 UTF-8 运行清单，记录运行标识、模式、选择范围、配置哈希、开始/结束时间、逐篇状态、警告与有限错误详情、统计和产物相对路径；产物与清单 MUST 采用原子替换，不能留下被视为成功的半写文件。

#### Scenario: 相同处理版本被安全复用

- **WHEN** 目标论文的完整产物已存在且清单中的输入、配置、解析器版本和产物哈希全部匹配
- **THEN** 系统 MUST 幂等跳过该论文或验证后复用产物，并在本次运行清单中记录跳过原因

#### Scenario: 不完整或被篡改的产物不被复用

- **WHEN** 任一预期文件缺失、JSON/JSONL 无法校验、产物哈希不匹配或上次状态不是成功
- **THEN** 系统 MUST 将旧产物视为不可复用，安全重建到临时目标，并 MUST 在完整校验成功后才发布新版本

#### Scenario: 可再生层被删除后重建

- **WHEN** `data/interim` 和 `data/processed` 被清空但原始 PDF、元数据及版本化配置保持不变
- **THEN** 系统 MUST 能重新生成与原处理版本语义和字节均一致的结构化文档、Paper 与 Chunk 产物

### Requirement: 有界摄取编排与逐篇失败隔离

系统 MUST 提供统一摄取入口，支持 dry-run、pilot、显式单篇和有界批量模式，并允许调用方指定配置、输入/输出根目录及最大论文数。入口 MUST 在执行前展示或返回解析后的选择范围和配置摘要；批处理 MUST 隔离单篇失败、继续剩余论文，并以非零退出状态和失败报告表示任何未成功论文。

#### Scenario: dry-run 不写入产物

- **WHEN** 调用方使用 dry-run 运行 pilot、单篇或批量选择
- **THEN** 系统 MUST 完成参数、清单、输入和配置校验并报告计划处理/跳过项，但 MUST NOT 创建或修改 interim、processed 或运行清单

#### Scenario: 单篇失败不终止批次

- **WHEN** 有界批次中的一篇论文损坏或解析失败而其他论文有效
- **THEN** 系统 MUST 记录该论文失败、继续处理其余论文、保留成功产物，并在最终摘要中准确报告成功、跳过、警告和失败数量

#### Scenario: 无界或冲突选择被拒绝

- **WHEN** 调用方请求超过配置安全上限的论文数、同时指定互斥模式，或指定不在已校验语料中的论文
- **THEN** 系统 MUST 在写入任何产物前返回不可重试输入错误

### Requirement: pilot 质量门禁与完整语料试跑

系统 MUST 为 pilot 运行保存可复核统计与人工抽检记录，至少覆盖页数、提取字符数、空文本页、警告类型、Section/Block/Chunk 数、Token 分布和页码覆盖。只有 pilot 全部产生有效结构化文档和 Chunk，且人工抽检未发现系统性页码错位、正文大面积缺失或跨栏乱序时，系统才 MUST 允许按显式选项执行完整语料有界试跑。

#### Scenario: pilot 达到扩展门禁

- **WHEN** pilot 中每篇论文均完成自动校验，且人工抽检记录对所有必需版面标签给出通过结论
- **THEN** 系统 MUST 生成可审计的门禁摘要，并允许完整语料试跑输出总体和逐篇统计

#### Scenario: pilot 质量不足阻止默认扩展

- **WHEN** 任一 pilot 论文缺少产物/抽检结论，或发现系统性页码、缺失文本、跨栏顺序问题
- **THEN** 系统 MUST 将门禁标记为失败并默认拒绝完整语料模式，同时保留失败论文、页面、警告和修复后重跑所需信息
