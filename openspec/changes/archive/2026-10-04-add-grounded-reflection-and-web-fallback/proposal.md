# Proposal

## Why

当前系统已经能定位内部证据缺口并有界停止，但尚未把纠错结果落实为经过语义支撑检查、逐结论可追溯的最终回答，也无法在明确的内部知识缺失时安全地补充外部资料。迭代 6 需要补齐这段受预算约束的回答闭环，使系统既能利用可信 Web 证据，又不会把未覆盖 facet 或模型参数知识包装成已证实事实。

## Goals

- 在内部纠错结果之后生成逐结论引用、可区分事实/归纳/推断/冲突的结构化回答。
- 以确定性校验为主、可替换 Critic 为辅，检查引用、语义支撑、归因、冲突与必需 facet 覆盖。
- 仅对明确的内部知识缺失执行一次受控 Web 兜底，并把结果转换为显式外部 `Evidence`。
- 通过共享预算和结构化决策，将反思限定为一次重新生成、一次预算内重新检索或保守终止。
- 提供默认离线、可复现的验收与指标，真实 Web 只作为显式的小规模 smoke。

## Non-goals

- 不提供自主浏览、页面交互、登录、付费内容访问、爬取站点或任意工具调用。
- 不把 LLM 参数知识、搜索摘要或无法复核的内容视为检索证据。
- 不在本 change 中提供公共 HTTP API、前端界面或完整的最终研究实验。
- 不放宽迭代 5 已建立的内部纠错轮次、Token 和候选规模上限。

## What Changes

- 新增严格的回答、结论—引用映射、引用验证、回答评估和最终结果契约，并将结论关联到已有 facet 覆盖记录。
- 新增确定性检查器和版本化 Critic Prompt；确定性检查优先，Critic 仅判断难以规则化的语义支撑与错误归因。
- 新增最小 `SearchProvider` 边界、可信来源策略和 Web 结果转换器，校验 URL、域名、摘录长度、来源类型及访问时间，并生成 `external=true` 的稳定 `Evidence`。
- 新增回答阶段工作流，在内部纠错结果之后按结构化状态选择回答、一次反思补救、受控 Web 或保守终止；所有分支共享原有预算身份并设独立硬上限。
- 新增原子检查点、脱敏 Trace、离线录制 fixture、回答与 Web 指标，以及显式的 5–10 题真实 Web 验收入口。

## Capabilities

### New Capabilities

- `grounded-reflection-web-fallback`: 规定可追溯回答、回答检查、单轮反思决策、受控 Web 外部证据、恢复与离线/在线验收的完整行为边界。

### Modified Capabilities

无。Dense RAG 仍是无反思、无 Web 的固定基线；现有内部纠错工作流仍只负责内部证据充分性与纠错，本能力消费其结构化终止结果而不改变其要求。

## Requirements Traceability

- 项目规格：`COR-006`、`COR-008`、`ANS-001`–`ANS-006`、`WEB-001`–`WEB-004`、`OBS-001`–`OBS-004`、`EVAL-006`–`EVAL-008`。
- 迭代依据：`../guidebooks/iteration-06-reflection-web.md`。

## Impact

- 预计新增或扩展回答/反思模型、生成与检查模块、Web Provider/策略模块、回答阶段工作流、配置、Prompt、评测入口、离线 fixture、文档和测试；重要路径变化在实施时同步 `../PROJECT_MAP.md`。
- 复用 `Evidence`、`EvidenceRequirement`、覆盖矩阵、纠错停止结果、预算账本、Trace、LLM Provider 和现有回答解析能力；不引入浏览器或自主 Agent 框架。
- Web Provider 是可注入依赖，默认禁用并使用 Mock/录制响应；真实搜索需要显式配置、确认问题数与最坏预算。

## Dependencies and Risks

- 依赖迭代 5 的 facet、覆盖矩阵、内部知识缺失停止原因、预算与检查点语义，以及现有版本化回答 Prompt 和引用解析器。
- Critic 可能产生误判或非法结构，因此其结果不能绕过确定性引用、facet 覆盖、预算与外部来源校验。
- 搜索结果可能失效、被截断或来源质量不足；系统必须拒绝非可信/不可解析结果，并在搜索失败时保守输出知识边界。
- 新的模型与搜索调用会增加时间、Token 和网络不确定性；默认离线路径、一次调用上限、有限上下文及检查点恢复用于限制成本。
