# Spec Delta

## Purpose

消除实时应用验收发现的跨段落伪冲突，使充分性判断只阻塞真正属于同一 facet、同一可比命题的相互矛盾 Evidence。

## MODIFIED Requirements

### Requirement: 结构化充分性、冲突与缺口诊断

系统 MUST 根据每个必需 facet 的有效匹配、最低支撑强度、独立来源数和阻断冲突生成结构化充分性结果。冲突 MUST 绑定同一 facet 下可比较的命题：系统 SHALL 优先使用 Evidence 中以相同 `normalized_value_key` 显式绑定的规范化值；只有指标或数值条件 facet 才可从文本中比较有单位或明确位置的指标值。普通正文中未绑定命题的年份、实体编号、实验数字、版本号或否定词 MUST NOT 单独构成阻断冲突。对于论文实体问题，系统 MUST 以单词边界匹配可区分的缩写、驼峰名或连接符名称；当这类强名称存在时，普通英文分类词不得替代目标实体，且四字符以内的歧义缩写在存在其他实体时必须至少再命中一个共同实体。同论文身份只允许用于有界补充候选，MUST NOT 让未满足 facet 条件的摘要、实验页或附录继承覆盖状态；系统 MUST 逐片段重新验证，并优先选择支撑强度与来源质量更高的 Evidence，再以重排、融合和检索排名打破平局。论文上下文 MUST 来自本次运行锁定的索引快照，不得扫描可漂移的处理目录。结果 MUST 区分已覆盖、缺失、冲突和需要人工复核，并保存参与判断的 Evidence 标识与有限原因。

#### Scenario: 首轮证据已经充分

- **WHEN** 所有必需 facet 均满足最小证据和支撑阈值且不存在阻断冲突
- **THEN** 系统 MUST 将状态标记为充分、保留选定 Evidence，并直接进入成功停止，不生成或执行纠错动作

#### Scenario: 比较缺侧定位到具体 facet

- **WHEN** 检索结果只支持比较对象的一侧而另一侧没有合格来源
- **THEN** 系统 MUST 将缺失侧对应的必需 facet 标记为未覆盖，给出有限诊断依据，而不得把总体相关性判为充分

#### Scenario: 冲突证据阻止虚假充分

- **WHEN** 两条有效 Evidence 对同一必需 facet 给出不能同时成立的结果且没有配置允许的解决依据
- **THEN** 系统 MUST 记录冲突来源、降低该 facet 的满足状态并保持证据不足，而不得静默选择分数较高的一条

#### Scenario: 指标 Evidence 报告不同数值

- **WHEN** 同一指标 facet 的两条有效 Evidence 分别报告可比的 80% 与 90%
- **THEN** 系统记录阻断数值冲突、保留两侧 Evidence，并不得把该 facet 判为充分

#### Scenario: 组件正文包含无关数字和否定词

- **WHEN** 同一组件 facet 的相关 Chunk 分别包含实验倍率、年份、编号或 `without` 等与组件命题无关的文本
- **THEN** 系统不得据此生成数值或否定冲突；满足支撑阈值与来源要求时该 facet 仍可判为充分

#### Scenario: Evidence 提供显式规范化值

- **WHEN** 两条 Evidence 为同一 facet 和相同 `normalized_value_key` 提供不同的 `normalized_value`
- **THEN** 系统按布尔、数值或离散值类型记录可审计冲突，不依赖整段文本中其他无关词项

#### Scenario: 同论文片段不继承覆盖

- **WHEN** 一篇已由实体锚定的论文同时返回答案段、实验页和附录，而后两者没有满足 facet 条件
- **THEN** 系统 MUST 只把逐片段验证通过的 Evidence 计入覆盖，不得仅凭相同 `paper_id` 把实验页或附录交给回答阶段

#### Scenario: 首个命中片段来自附录或实验页

- **WHEN** 初始 Hybrid Evidence 明确命中论文实体但没有承载问题所需定义、组件或机制
- **THEN** 实时应用 MUST 从当前冻结 Sparse 索引为首个锚定论文补入有界的摘要优先候选、按稳定 Chunk 来源去重并逐片段重新评估，且不得为此调用额外 Embedding、LLM 或扫描当前处理目录

#### Scenario: 基准名称与分类标签同时出现

- **WHEN** 问题包含 `ACEBench` 一类强项目名以及 `Normal`、`Special` 等普通分类标签，而候选 Evidence 只含分类标签或名称相近的另一基准
- **THEN** 系统 MUST 将目标强项目名作为实体门槛并拒绝该候选，不得由普通标签、会议名或相似名称把 facet 判为覆盖

#### Scenario: 简单问题存在跨语言检索缺口

- **WHEN** 中文问题包含 `MLR-Bench`、`AgentBench` 等可区分的拉丁项目名，而文献正文和 Web 页面主要使用英文术语
- **THEN** 系统 MUST 在 Facet LLM 已启用时把该问题纳入一次有界需求生成，为检索条件补充文献侧英文证据词；模型失败时仍原子回退规则 facet，不得硬编码具体论文词表

#### Scenario: 短缩写存在跨领域歧义

- **WHEN** 问题以四字符以内缩写指代方法且同时给出数据集、框架或其他目标实体
- **THEN** 证据除按边界命中该缩写外还 MUST 命中至少一个共同实体，单独出现同形缩写不得建立论文锚点
