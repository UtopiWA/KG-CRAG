# Proposal

## Why

当前已完成版本化 API、固定回放、阶段性 Streamlit 界面和低资源启动骨架，但默认应用服务仍未装配真实查询工作流：用户只能选择预置案例，任意问题会因 `live_query` 缺失返回 503。这不足以证明项目能够实际处理开放输入；现有单页界面也不具备用户熟悉的对话历史与逐轮诊断体验。

本 change 对应 `../guidebooks/iteration-08-application.md`。它继续只包装已经存在的工作流能力，并把已完成的回放骨架扩展为真实任意问题主路径和 Gradio 对话界面；它不依赖迭代 7 的正式测试结果，也不得创建或消费正式测试锁。

## Goals

- 提供版本化、严格校验且可注入替身的科研问答、论文查看、受控摄取和 Trace 查询 API。
- 把任意合法用户问题装配到现有检索、充分性判断、纠错和回答工作流，不要求问题预先存在于 fixture。
- 提供只调用公共 API 的 Gradio GPT 式对话界面，展示会话、答案、引用、来源类型、facet 覆盖、路由、纠错动作和预算状态。
- 提供按需启动、资源有界、可持久化且可诊断的本地运行方案。
- 在外部服务不可用时，使用明确标记的固定回放案例保留演示和诊断能力。

## Non-goals

- 不另建一套 Dense、Sparse、Graph、Web、Agent、充分性判断或回答生成逻辑；真实链路验收发现的既有契约缺陷可以在原模块修正并补充对应 capability delta。
- 不执行迭代 7 的一次性正式测试，不使用测试集调试 API 或界面。
- 不提供公网部署、多租户、账户权限、分布式任务队列或生产级高可用能力。
- 不允许界面以自由文本控制内部路由、阈值、Prompt 或工具调用。
- 不在演示请求期间重建语料或索引，也不把模型权重、论文、缓存或密钥打入镜像。

## What Changes

- 新增 `/v1` 公共 API 契约，通过应用服务 Protocol 调用现有工作流；API 层不复制检索、纠错和回答决策。
- 新增统一错误信封、请求关联 ID、超时和取消语义，并区分输入错误、依赖不可用、预算停止与内部错误。
- 新增真实查询应用服务，按配置惰性装配 Dense、Sparse、可选 Graph、纠错、回答和受控 Web；内部证据不足时返回保守知识边界。
- 以 Gradio 对话界面替换阶段性的 Streamlit 单页界面；实时查询是主路径，三类固定案例和 Trace 回放仅作为显式降级路径。
- 新增存活、就绪和依赖状态检查；外部依赖不可用时可显式切换到脱敏回放数据，但不得伪装成实时结果。
- 调整 Compose 为显式 profile 按需启动 API、UI、Qdrant 和 Neo4j，并记录内存、持久化目录、模型缓存和故障排查约束。
- 增加小型端到端烟雾测试和干净环境演练；这些演练只使用开发数据或固定回放，不构成正式评测。

## Capabilities

### New Capabilities

- `query-application`: 版本化查询 API、任意问题真实工作流、Gradio 对话界面、运行健康状态、固定回放和低资源本地打包契约。

### Modified Capabilities

- `evidence-sufficiency-corrective-workflow`：冲突必须绑定同一可比命题，普通正文中的无关数字或否定词不得产生阻塞冲突。
- `grounded-reflection-web-fallback`：回答生成失败必须分类诊断，Provider 实际用量与保守估算必须区分，并把回答阶段的最终纠错状态交给应用层。

## Impact

- 主要影响 `src/kg_crag/api/`、应用服务适配层和 `ui/`，以及回答解析、冲突检测、公共 schema、配置、Compose、测试和运行文档。
- 依赖 `foundation-contracts`、`grounded-reflection-web-fallback` 及其他已归档检索能力；迭代 7 的评测 change 可保持未归档，二者不共享正式测试产物。
- Gradio 应作为可选依赖安装，默认单元测试不启动服务器、数据库、模型或网络请求；已有 Streamlit 阶段产物在 Gradio 等价验收后移除。
- 主要风险是公共响应泄漏内部状态、API 与工作流重复、容器常驻资源过高和回放结果被误认为实时结果；通过严格投影、单一应用服务边界、profile/硬上限和显式模式标签控制。
