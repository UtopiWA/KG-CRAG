# Proposal

## Why

当前检索、纠错与溯源能力主要通过包内接口和脚本使用，HTTP 层仅有存活检查，缺少稳定的查询契约、可诊断界面和低资源启动方式。这使项目难以在不理解内部实现的情况下演示，也难以在 Qdrant、Neo4j、模型或 Web 服务不可用时解释降级行为。

本 change 对应 `../guidebooks/iteration-08-application.md`。它只包装已经存在的工作流能力，不依赖迭代 7 的正式测试结果，也不得创建或消费正式测试锁。

## Goals

- 提供版本化、严格校验且可注入替身的科研问答、论文查看、受控摄取和 Trace 查询 API。
- 提供只调用公共 API 的最小演示界面，展示答案、引用、来源类型、facet 覆盖、路由、纠错动作和预算状态。
- 提供按需启动、资源有界、可持久化且可诊断的本地运行方案。
- 在外部服务不可用时，使用明确标记的固定回放案例保留演示和诊断能力。

## Non-goals

- 不新增或重写 Dense、Sparse、Graph、Web、Agent、充分性判断或回答生成逻辑。
- 不执行迭代 7 的一次性正式测试，不使用测试集调试 API 或界面。
- 不提供公网部署、多租户、账户权限、分布式任务队列或生产级高可用能力。
- 不允许界面以自由文本控制内部路由、阈值、Prompt 或工具调用。
- 不在演示请求期间重建语料或索引，也不把模型权重、论文、缓存或密钥打入镜像。

## What Changes

- 新增 `/v1` 公共 API 契约，通过应用服务 Protocol 调用现有工作流；API 层不复制检索、纠错和回答决策。
- 新增统一错误信封、请求关联 ID、超时和取消语义，并区分输入错误、依赖不可用、预算停止与内部错误。
- 新增最小 Streamlit 界面，通过 API 展示三类固定案例及结构化 Trace 摘要。
- 新增存活、就绪和依赖状态检查；外部依赖不可用时可显式切换到脱敏回放数据，但不得伪装成实时结果。
- 调整 Compose 为显式 profile 按需启动 API、UI、Qdrant 和 Neo4j，并记录内存、持久化目录、模型缓存和故障排查约束。
- 增加小型端到端烟雾测试和干净环境演练；这些演练只使用开发数据或固定回放，不构成正式评测。

## Capabilities

### New Capabilities

- `query-application`: 版本化查询 API、最小演示界面、运行健康状态、固定回放和低资源本地打包契约。

### Modified Capabilities

无。本 change 复用现有能力的公共契约，不修改检索、纠错、回答、评测或 Trace 的领域语义。

## Impact

- 主要影响 `src/kg_crag/api/`、新增的应用服务适配层和 `ui/`，以及公共 schema、配置、Compose、测试和运行文档。
- 依赖 `foundation-contracts`、`grounded-reflection-web-fallback` 及其他已归档检索能力；迭代 7 的评测 change 可保持未归档，二者不共享正式测试产物。
- Streamlit 应作为可选依赖安装，默认单元测试不启动服务器、数据库、模型或网络请求。
- 主要风险是公共响应泄漏内部状态、API 与工作流重复、容器常驻资源过高和回放结果被误认为实时结果；通过严格投影、单一应用服务边界、profile/硬上限和显式模式标签控制。
