# Design

## Context

项目已经具备检索、证据统一、充分性判断、纠错、回答和 Trace 领域能力，并已完成 `/v1` API、回放服务、阶段性 Streamlit 页面与 Compose profiles。当前缺口是默认 `DefaultApplicationService` 没有装配 `GroundedAnswerQueryAdapter` 的真实执行函数，因而开放问题无法进入现有工作流；同时 Streamlit 单页仅适合固定案例展示。直接在 API 或新界面中重写路由会形成第二套行为语义，并扩大敏感信息和无界正文泄漏风险，因此仍需通过单一应用服务边界完成真实装配。

迭代 7 的统一评测仍保留一次正式测试未执行。本 change 的所有样例、烟雾测试和回放均使用开发侧小型 fixture，不读取正式测试题、不写正式运行记录，也不改变开发选择记录。

## Goals / Non-Goals

**Goals:**

- 把现有工作流包装为稳定、严格、可替换依赖的应用服务和 `/v1` HTTP 契约。
- 让任意合法问题在真实模式下经过现有检索、facet 诊断、纠错和有依据回答，而不是只能选择固定回放。
- 让非开发者能够从界面理解回答依据、证据来源、缺失 facet、纠错过程和资源停止原因。
- 在 16 GB 宿主机上按需启动最少组件，并给出 10 GB 目标、12 GB 硬上限的运行约束。
- 提供不依赖真实数据库或在线模型的可重复演示与自动化测试路径。

**Non-Goals:**

- 不让 HTTP 模型成为新的领域模型，不从 API 参数开放内部策略选择与调参能力。
- 不实现任务队列、并发批处理、账户、权限、公网 TLS 或跨主机编排。
- 不借迭代 8 演示重新运行评测、重新冻结数据或提前形成实验结论。

## Decisions

### 1. 使用“公共传输模型 → 应用服务 Protocol → 现有工作流”的单向边界

API 请求先解析为严格的公共命令，再交给 `QueryApplicationService`、`DocumentApplicationService`、`IngestionApplicationService` 和 `TraceApplicationService` 等窄 Protocol。默认实现只编排已有包内入口；测试和回放实现可注入确定性替身。路由函数不得直接构造 Retriever、图客户端、LLM Provider 或 Agent，也不得重现充分性和纠错判断。

公共响应只投影回答、稳定 Evidence/来源引用、facet 状态、动作摘要、预算摘要和受限诊断字段。内部 Prompt、原始 Provider 响应、完整正文、私有推理、连接串和密钥不进入公共模型。

### 2. API 以 `/v1` 为稳定前缀，并保持摄取范围同步且有界

第一版提供以下资源：

- `POST /v1/queries`：执行单个问题，支持显式的实时或回放模式，但不接收内部策略、阈值和 Prompt。
- `GET /v1/documents/{paper_id}`：读取有界论文元数据、处理状态和 Chunk/Evidence 引用，不返回整篇正文。
- `POST /v1/ingestion/runs`：执行 dry-run 或受限的小批量摄取并同步返回结果；不引入持久任务队列。
- `GET /v1/traces/{trace_id}`：读取脱敏、有界、按序的 Trace 摘要。
- `GET /health` 与 `GET /ready`：分别表达进程存活和依赖就绪/降级状态。

摄取默认 dry-run，实际执行必须显式确认并受论文数、文件大小、超时和并发上限约束。同步语义避免引入仅用于演示的任务基础设施；客户端断开或服务超时触发协作式取消，已完成的原子产物遵循原摄取契约，不伪装为整批成功。

### 3. 统一错误信封，响应状态不暴露内部异常

公共错误包含稳定 `code`、中文安全消息、`request_id`、是否可重试及有界字段级详情。输入或状态冲突使用 4xx，依赖未就绪使用 503，应用超时使用 504，未分类异常使用脱敏 500。日志可通过 `request_id` 和 `trace_id` 关联，但不得把堆栈、凭据或原始响应返回客户端。

超时、取消、预算停止和依赖降级是不同状态。任何未完成请求都不得返回成功响应；系统也不得在用户不可见的后台继续触发 LLM、Web 或摄取调用。

### 4. Gradio 提供 GPT 式会话体验，但仍只是 API 客户端

界面通过可配置 API 基址调用 `/v1`，不导入 Retriever、工作流图或 Provider。Gradio 页面使用聊天气泡、输入框、发送/停止/清空操作和示例问题；每轮回答旁提供引用、内部/Dense/Sparse/Graph/Web 来源、facet、路由与纠错时间线、预算和停止原因的折叠诊断区。

会话历史保存在 Gradio session state 中，默认不作为下一轮工作流输入；若未来需要多轮语义上下文，必须另行定义公共契约和预算。界面只允许控制是否允许 Web、是否返回 Trace 以及显式实时/回放模式，不开放任意 Prompt、阈值、路由或工具名称。Gradio 作为 `demo` 可选依赖，核心包与默认测试不因其缺失而失败；现有 Streamlit 页面在 Gradio 完成等价验收后删除。

### 5. 真实模式装配完整但有界的现有工作流

真实 `LiveQueryApplicationService` 读取版本化配置与当前索引身份，依次调用已有问题 facet 生成、Dense/Sparse Hybrid 检索、充分性评估、有界纠错和 grounded answer 工作流。Graph 仅在配置启用且健康时作为候选工具；Web 仅在内部知识不足、请求允许且既有可信来源门禁通过时触发。应用适配层只负责编排和公共投影，不实现新的检索、评分或决策规则。

任意非空且长度合规的问题都可进入该路径，不需要 question ID 或 fixture。系统不承诺所有问题均有答案：证据充分时返回带稳定引用的回答，内部知识不足且不能安全补全时返回保守知识边界，依赖或预算失败时返回结构化失败。禁止根据问题文本自动匹配回放案例。

配置必须冻结语料、Dense/Sparse/Graph 索引版本、模型、Prompt 和预算；启动时只做轻量身份与健康检查，模型保持惰性加载。一次请求继续遵守既有循环、候选、Token、Web 和时长硬上限，并支持取消后停止尚未开始的调用。

### 6. 回放是显式运行模式，不是静默降级

仓库保存三个小型、脱敏且版本化的回放案例：内部证据充分、纠错补全缺失 facet、外部依赖不可用后的保守停止。每项记录固定公共响应和 Trace 摘要，不包含论文大段正文或模型原始输出。

用户选择实时模式而依赖不可用时，API 返回结构化未就绪/降级信息，不自动把回放冒充实时结果。只有显式选择回放模式时才返回回放，并在响应和 UI 显著标记 `replay`、fixture 版本和非实验结论声明。

### 7. Compose 使用显式 profile 和可配置持久化路径

API、UI、Qdrant 和 Neo4j 均通过命名 profile 按需启动；文档提供最小回放、检索存储、图增强三种组合。默认命令不应无意常驻全部服务。存储卷与模型缓存路径可由环境配置到空间充足的磁盘，镜像不复制 `.env`、论文、权重、缓存、数据库卷和运行报告。

服务声明健康检查、重启和内存约束。完整应用峰值以内存 10 GB 为目标、12 GB 为硬停止边界；BGE 与重排器延迟加载，不同时常驻 GPU。Neo4j 使用小内存配置，Graph 始终是可选工具，未启用时不影响 Dense/Sparse 或回放路径。

### 8. 验收烟雾测试与正式评测完全隔离

离线端到端验收运行三个固定开发侧案例，验证 API、界面投影、Trace 下钻、依赖降级和资源配置。另以少量非 fixture 开发问题执行一次受控真实烟雾测试，覆盖直接回答、需要纠错和内部知识不足；它只验证链路可运行，不用于估计正式效果。

烟雾测试不得读取统一评测 test split，不得调用 `--confirm-test-run`，不得创建正式锁或把结果写入最终实验表。迭代 9 只有在迭代 0～8 行为冻结且用户再次明确确认后，才可消费一次性正式测试。

## Risks / Trade-offs

- [同步摄取可能占用请求较久] → 严格限制批量、并发与超时，并把大规模摄取继续留给已有 CLI，而不是引入任务队列。
- [公共响应可能与内部模型漂移] → 通过单向投影和契约测试固定字段，只让应用适配层理解内部模型。
- [回放降低“真实运行”感] → 明确模式标签，并提供可选实时 profile；回放服务于演示和故障诊断，不用于宣称效果。
- [任意问题可能超出本地语料] → 把“已处理”定义为有证据回答、保守知识边界或结构化失败之一，不强迫模型猜测。
- [Gradio 会话外观可能被误解为多轮记忆] → 明示历史仅用于展示，服务端每轮问题保持独立，后续多轮上下文另行变更。
- [Compose 内存限制在不同运行时表现不同] → 同时提供声明式限制、进程内硬门禁和人工观测命令，不把单一容器字段视为全部保障。
- [迭代 7 仍未归档] → 本 change 不修改其评测 capability、数据或正式锁；若后续评测模型变化，只调整应用层投影并重新验收。

## Migration Plan

1. 先增加公共 API 模型、错误信封和应用服务 Protocol，用替身冻结契约。
2. 实现 `/v1` 路由、依赖注入、超时/取消和就绪检查，保留旧 `/health` 兼容入口。
3. 增加回放包和阶段性 Streamlit 客户端，完成三个固定案例的离线演练。
4. 装配真实查询服务并用非 fixture 开发问题完成有界链路测试。
5. 以 Gradio 对话界面替换 Streamlit，验证历史、清空、模式标记和诊断下钻。
6. 调整 Compose profile、持久化与资源配置，更新 README、运维文档和项目地图。
7. 在干净环境运行默认检查及固定/真实烟雾测试；不执行正式测试，迭代 7 change 继续保持未归档。

若需要回滚，停止公开 UI/profile 并保留 `/health`；应用服务边界是新增适配层，不替换现有工作流和脚本，因而原能力可继续独立运行。
