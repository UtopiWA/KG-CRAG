# Spec Delta

## Purpose

把既有科研问答工作流包装为稳定、可诊断、资源有界的本地应用，同时确保界面、API、容器和回放不会复制领域逻辑、泄漏敏感内容或误用正式测试集。

## ADDED Requirements

### Requirement: 版本化且严格的公共 API

系统 SHALL 在 `/v1` 下提供单问题查询、论文摘要、受控摄取和 Trace 摘要资源，并 MUST 使用拒绝未知字段的严格请求与响应模型。公共响应只能包含有界答案、稳定引用、来源类别、facet/动作/预算摘要和脱敏诊断；完整正文、Prompt、私有推理、原始 Provider 响应、凭据和连接信息 MUST NOT 出现在公共模型中。

#### Scenario: 单问题查询返回可解释结果

- **WHEN** 客户端提交满足长度和模式约束的单个问题且应用服务成功完成
- **THEN** API 返回版本、request/trace ID、答案、稳定引用、来源类型、facet 覆盖、动作和预算摘要，且响应通过公共 schema 校验

#### Scenario: 公共投影使用回答阶段最终状态

- **WHEN** 回答工作流在初始 correction 之后执行二次内部检索并更新覆盖、冲突或动作历史
- **THEN** API MUST 投影回答终止时的 facet 状态、Evidence、冲突与完整动作历史，不得把回答前状态与回答后停止原因组合成同一响应
- **AND** Token 摘要 MUST 标明来自 Provider 实际 usage、保守估算或二者混合

#### Scenario: 未知字段或敏感输出被拒绝

- **WHEN** 请求包含未声明字段，或应用投影尝试写入完整正文、Prompt、原始响应、凭据或无界诊断
- **THEN** 系统在发布响应前拒绝输入或输出，并返回不含原始敏感值的结构化错误

### Requirement: 单一应用服务边界与可替换依赖

API 与 UI SHALL 只通过窄应用服务 Protocol 调用现有查询、论文、摄取和 Trace 能力。HTTP 路由和界面 MUST NOT 直接构造 Retriever、数据库或模型 Provider，也 MUST NOT 重算路由、充分性、纠错或回答决策；默认测试 MUST 可注入确定性替身而不访问网络或启动外部服务。

#### Scenario: HTTP 层复用现有工作流决策

- **WHEN** 查询应用服务返回 Evidence、facet、动作、停止原因和预算结果
- **THEN** API 只执行严格公共投影并保持稳定 ID 与顺序，不增加、删除或重新判断领域决策

#### Scenario: 默认测试隔离外部依赖

- **WHEN** 在未启用真实服务开关的情况下构造测试应用
- **THEN** 应用只注入替身或回放实现，且不得创建 LLM、Web、Qdrant 或 Neo4j 客户端

### Requirement: 有界摄取、超时、取消与错误语义

摄取 API SHALL 默认为 dry-run，实际运行 MUST 要求显式确认并受论文数、文件大小、并发和总时长的代码硬上限约束。所有 API 调用 MUST 具有请求关联 ID 和超时；输入错误、状态冲突、依赖不可用、预算停止、超时/取消与内部错误 MUST 使用稳定错误码区分。客户端取消或服务超时后，系统 MUST 停止尚未开始的外部调用，且不得把部分结果表示为完整成功。

#### Scenario: 受控摄取在硬上限内执行

- **WHEN** 客户端显式确认实际摄取且输入、批量、文件和超时均在硬上限内
- **THEN** 系统调用已有摄取入口并返回逐项状态、稳定产物引用和完整/部分结果标志

#### Scenario: 超时阻止后续副作用

- **WHEN** 查询或摄取达到配置超时，或客户端在下一次外部调用前取消请求
- **THEN** 系统返回结构化超时/取消状态，停止后续 LLM、Web 或摄取调用，并保留已完成原子产物的真实状态

### Requirement: 存活、就绪与明确降级状态

系统 SHALL 分离进程存活与依赖就绪语义：`/health` 只表明 API 进程可响应，`/ready` MUST 以有界结构报告必需和可选组件的就绪、未启用或降级状态。状态响应 MUST NOT 泄漏密钥、连接串、内部路径或异常堆栈；可选 Graph 或 Web 不可用不得错误地把其他可用路径标记为整体宕机。

#### Scenario: 可选 Graph 未启用

- **WHEN** API 正常且 Dense/Sparse 或回放路径可用，但 Neo4j profile 未启动
- **THEN** `/health` 返回存活，`/ready` 将 Graph 标为未启用或降级，并准确报告仍可使用的查询模式

#### Scenario: 必需依赖未就绪

- **WHEN** 实时模式需要的必需存储或模型不可用
- **THEN** `/ready` 和查询错误返回稳定组件类别与可重试状态，不返回底层异常、地址或凭据

#### Scenario: 实时模型显式预热

- **WHEN** 实时模式启用模型预热且固定 revision 的 BGE 或重排器仍在加载
- **THEN** `/health` 继续可响应，`/ready` 将实时组件标记为 `warming`，实时查询返回可重试状态而不是无反馈地阻塞，回放查询仍保持可用
- **AND** 模型加载不得阻塞 API 事件循环，完成后状态转为 `ready`，失败则转为不泄漏路径或底层异常的 `degraded`

### Requirement: 任意问题进入真实且有界的问答工作流

实时模式 SHALL 接受任意非空且满足公共长度约束的问题，不得要求问题具有预置 question ID、fixture 或回放案例。系统 MUST 通过单一应用服务编排既有 facet 生成、Dense/Sparse Hybrid 检索、充分性判断、有界纠错和 grounded answer；Graph MUST 保持可选，Web 只有在内部知识不足、请求允许且可信来源门禁通过时才可触发。每次请求 MUST 返回带稳定引用的有依据回答、明确的保守知识边界或结构化失败之一，且不得为了给出答案而绕过证据与预算门禁。

#### Scenario: 非 fixture 问题获得有依据回答

- **WHEN** 用户提交一个未出现在回放或评测 fixture 中的问题，且当前内部语料能够覆盖其必需 facet
- **THEN** 系统运行真实检索与回答工作流，返回带内部 Evidence 引用、检索路径、facet 覆盖、预算和 Trace 的实时结果

#### Scenario: 复杂问题使用有界 Facet LLM

- **WHEN** 问题被规则分析识别为复杂问题且 Facet LLM 已配置
- **THEN** 系统 MUST 在初始检索前最多调用模型一次，以严格 Schema 生成证据需求并把实际或保守估算用量计入纠错预算
- **AND** `required=true` 的需求 MUST 只拆分用户明确询问的子问题，不得自行增加论文原文确认、背景、实验指标、组件或比较维度；Provider 返回的可选需求不得被提升为必需项
- **AND** 生成结果 MUST 在运行身份中冻结并由后续工作流复用；非法、超时或失败响应 MUST 整批回退规则 facet，不得接纳部分候选或重复隐藏调用

#### Scenario: 多证据问题保留有界证据包

- **WHEN** Dense 与 Sparse 共同召回支持多个必需 facet 的不同片段
- **THEN** 融合、重排、充分性选择与回答上下文 MUST 使用一致且可配置的有界候选规模，使最多 12 条选定 Evidence 能进入回答阶段，而不突破 16000 字符上下文上限
- **AND** 同论文扩展片段 MAY 作为有界上下文进入候选，但只有命中目标实体与 facet 条件的 Evidence 才能建立覆盖；ACL、LLM、Chain-of-Thought 等泛词不得单独把其他论文判为充分

#### Scenario: Tavily Web 兜底受三重门禁

- **WHEN** 内部证据不足且部署已配置 Tavily Provider 与密钥，并且当前请求显式允许 Web
- **THEN** 系统 MAY 执行最多一次、最多 5 条可信来源结果的搜索，并把结果标记为外部 Evidence
- **AND** 中文问题与英文结果 MAY 通过明确的论文简称或实体组合建立待复核绑定，且标题与摘要仍须经过可信域名、引用及回答检查
- **AND** 缺少 Provider、密钥或请求许可时 MUST 不执行搜索，也不得把 Web 描述为已成功启用

#### Scenario: 语料内组件问题不被无关数字阻塞

- **WHEN** 用户询问论文中的组件或流程，命中正文同时包含年份、编号、实验指标或与该命题无关的否定表达
- **THEN** 系统只依据同一可比命题判断冲突；无关数字和否定词不得把已充分 Evidence 标为冲突或缺失

#### Scenario: 任意问题超出可用知识

- **WHEN** 用户问题未获得充分内部证据，且 Web 未允许、不可用或仍不能补全必需 facet
- **THEN** 系统返回说明缺失 facet 和已尝试路径的保守知识边界，不生成未经 Evidence 支持的确定性结论

#### Scenario: 回放不能冒充任意问题处理

- **WHEN** 实时问题与某个固定回放问题文本相似或依赖发生失败
- **THEN** 系统仍按实时工作流处理或返回结构化失败，不得通过文本匹配自动返回回放答案

### Requirement: 只消费公共 API 的 Gradio 对话界面

演示界面 SHALL 使用 Gradio 提供类似 GPT 的聊天气泡、输入、发送、停止、清空和示例问题体验，并 SHALL 只调用版本化 HTTP API。每轮结果 MUST 展示答案以及可折叠的引用、来源类型、facet 覆盖、路由与纠错动作、预算、停止原因和 Trace；内部、Dense、Sparse、Graph 与 Web 来源 MUST 能被清晰区分。界面只允许是否使用 Web、是否返回 Trace 以及实时/回放等有界公开选项，不得提供自由文本 Prompt、阈值、路由或工具控制。

会话历史 MUST 默认仅保存在当前 UI session 用于展示；除非后续规格明确定义多轮上下文、截断和预算语义，否则 UI MUST 每轮只把当前用户问题发送给查询 API。实时模式应作为依赖就绪时的默认路径，固定回放只能由用户显式选择且必须持续显示非实时标签。

#### Scenario: 用户连续提交两个独立问题

- **WHEN** 用户在同一 Gradio 会话中依次提交两个问题且未启用任何未来的多轮上下文能力
- **THEN** 界面保留两轮可视历史，但第二个 API 请求只包含第二个问题和公开控制项，不隐式拼接第一轮内容

#### Scenario: 用户下钻纠错过程

- **WHEN** 查询包含初始缺失 facet 和后续纠错动作
- **THEN** 界面按 API 顺序展示缺失/已覆盖 facet、所用来源、动作、停止原因和关联 Trace，而不自行推断新结论

#### Scenario: API 返回安全失败

- **WHEN** API 返回依赖未就绪、预算停止、超时或未知错误信封
- **THEN** 界面显示 request ID、可重试性和安全中文说明，不显示堆栈、原始响应或本地连接细节

#### Scenario: 宿主机代理不阻断本地界面自检

- **WHEN** UI 进程继承 HTTP/HTTPS 代理且既有代理例外未包含 localhost
- **THEN** 启动入口 MUST 在保留既有代理例外的同时为当前进程补入 `localhost`、`127.0.0.1` 和 `::1`，并显式保持 `share=false`，不得因本地自检失败创建公网分享链接

#### Scenario: 用户停止或清空会话

- **WHEN** 用户停止正在执行的请求或清空当前对话
- **THEN** 界面取消尚未完成的客户端任务或清除 session 展示状态，且不得把已取消请求显示为成功回答

### Requirement: 显式且版本化的离线回放

系统 SHALL 提供内部证据充分、纠错补全和保守停止三个小型脱敏回放案例。回放 MUST 具有稳定 fixture 版本、固定公共响应与 Trace 摘要，并 MUST 在 API 和界面中显著标记为 `replay` 及“非实时、非正式实验结果”。实时依赖失败时系统 MUST NOT 静默返回回放结果。

#### Scenario: 用户显式选择回放

- **WHEN** 用户选择已知回放案例和受支持的 fixture 版本
- **THEN** 系统无需数据库、模型或网络即可返回确定性结果，并在每个结果中保留回放模式和版本标签

#### Scenario: 实时模式依赖失败

- **WHEN** 用户请求实时模式但必需依赖不可用
- **THEN** 系统返回依赖未就绪或降级响应，可建议用户选择回放，但不得自动以回放内容返回成功

### Requirement: 按需、持久且资源有界的本地打包

API、UI、Qdrant 和 Neo4j SHALL 通过显式 Compose profile 按需启动，并 MUST 提供健康检查、资源限制和可配置持久化/模型缓存路径。未选择的 profile MUST NOT 常驻；Graph MUST 保持可选。镜像 MUST NOT 包含 `.env`、密钥、论文、模型权重、缓存、数据库卷或运行报告。完整应用以内存峰值低于 10 GB 为目标，超过 12 GB 的配置或观测 MUST 阻止继续加载可选模型/服务并给出恢复说明。

#### Scenario: 最小回放 profile 启动

- **WHEN** 用户只启用最小回放所需 profile
- **THEN** API 和 UI 可完成三个固定案例，Qdrant、Neo4j、BGE、重排器和在线模型均不被启动或加载

#### Scenario: 持久化路径空间不足

- **WHEN** 配置的数据库或模型缓存路径不可写、空间不足或超过资源硬边界
- **THEN** 系统在下载模型、重建索引或启动可选重服务前失败，并报告安全的配置项和迁移/清理建议

#### Scenario: 一次性准备固定模型

- **WHEN** 用户显式运行模型准备入口
- **THEN** 系统只准备配置中固定 revision 的 BGE 与可选重排器，并把两者写入同一个可配置缓存根目录
- **AND** 后续实时启动 MUST 默认只从该目录解析固定模型、禁止上游库进行远端版本或配置探测，回放启动仍不得加载这些权重

### Requirement: 演示验收与正式评测隔离

应用验收 SHALL 只使用开发侧小型 fixture、替身或回放，并 MUST 覆盖三个固定案例、Trace 下钻、超时取消和依赖降级。验收流程 MUST NOT 读取统一评测 test split、接受正式测试确认标志、创建正式测试锁或把烟雾结果发布为实验结论。

#### Scenario: 固定案例端到端验收

- **WHEN** 在干净环境运行应用烟雾测试
- **THEN** 三个案例均通过 API 和公共投影完成，且运行记录明确标记为开发演示而非正式评测

#### Scenario: 演示命令尝试消费正式测试

- **WHEN** 应用验收输入引用 test split、正式运行确认或正式测试锁路径
- **THEN** 系统在读取测试题正文或调用被评系统前拒绝执行，并保持现有正式测试状态不变
